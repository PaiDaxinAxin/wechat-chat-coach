# Single conversation design

The owner requested one simulated WeChat conversation on 2026-09-30: the counterpart's messages and the user's pending reply are the main content; AI advice appears inside that conversation. The owner initially declined a separate AI chat; on 2026-10-01 the owner explicitly added a companion part named 场外教练 for whole-topic monitoring and evaluating the user’s initiative plans. The owner also requested day and night colors and deferred email, login and website authorization work for the local demo.

## Reference and scope

Read-only source: [LYNCA Design Standard 1.4.0](https://linear.app/lynca/document/infralynca-design-standard-505c197ca09a), effective 2026-10-02, canonical `updatedAt` `2026-10-02T14:47:48.520Z`. Its less-is-more hierarchy, truthful states, typography roles, keyboard access, minimum touch targets and restrained composition apply here. The implementation reference is the owner-export-checked Nocturne snapshot of 2026-09-07 and LYNCA overlays.

The personal project's visual values have one implementation home, `web/styles.css`. Night base roles, spacing, radii and font stacks follow the reference. The day palette and accent-tinted speaker bubbles are scoped product decisions for this chat demo, rather than changes to the company's design system. The same hierarchy and controls apply to both themes. Chat bubbles and compact controls use the UI font stack; long reading/display retains the serif role. No remote font dependency or glass chrome is required.

## Composition and behavior

- One conversation surface: counterpart messages on the left, self messages and editable pending replies on the right. AI analysis, direction choices and next-step advice are identified as advice within the thread.
- A small header selects the counterpart and opens supplementary actions. No always-visible directory, heat dashboard or questionnaire. The companion field coach follows the owner’s later explicit addition.
- Personal profile, counterpart background and meeting arrangements open only when needed, inside the same conversation. Follow-up messages automatically form raw feedback for the preceding draft. Unknown observations remain unknown; lower-weight directions remain selectable.
- The composer records pasted messages and continues the previous round without separate sent-confirmation or feedback buttons. Eligible complete contexts automatically obtain three direction weights once; a direction click generates that reply. Generated and inferred texts retain their source status; the software does not send messages to WeChat.
- Day/night switching preserves the current conversation and unsaved drafts. Only the theme preference belongs in browser local storage; private profiles, chats, tokens and API credentials do not.
- Local demo stays explicitly fictional and loopback-only, with separate private data. Its automatic session never becomes a public authentication bypass. Public access and personal email delivery remain deferred.

## Field coach amendment — 2026-10-01

The owner added a companion part named 场外教练, overriding the earlier single-part restriction. Desktop places it beside the simulated conversation; narrower layouts open the same part from the header so the message composer remains available. It monitors the complete topic, initiative, warming/obstacle cadence and evidence, and accepts the user’s proposed plan for explicit evaluation. Routine monitoring shares direction-analysis results; plan evaluation is a separate deliberate model call, bounded by daily budgets and never inserted as a WeChat reply. One round means a complete topic. A 10–20-message topic checkpoint is an experience-based prompt to inspect repetition and engagement, not a fixed boredom threshold. User-corrected timestamps replace the primary visible time and analysis reference, with original entry receipts retained privately.

The owner subsequently requested a concise action guide. The default coach view shows the existing server-derived heat index rounded to the nearest five degrees, followed by three priorities: the direction of the next conversation (后续对话的方向), what to avoid, and a concrete way to respond (接话方式). This is a provisional interaction index, not a success probability. Sparse observed evidence now yields a broad server-derived preliminary range while the mature score and ranking gates remain unchanged. Missing observations show a brief analysis or first-message prompt; explicit negative resistance suppresses the number and overrides warming or invitation advice. Coverage counts observed dimensions, not independent messages. Long historical text, its conditions and negations remain intact behind visual previews and the evidence disclosure. The primary direction remains the highest actual recommendation weight, with tied directions marked as alternatives; choosing another direction does not silently redefine the recommendation.

New model instructions request one concrete conversation direction, one immediately useful action and one evidence-grounded pitfall, preferably within 40 characters each. The optional pitfall field preserves old results; missing historical pitfalls use a labeled generic reminder, never an invented personal trait. Detailed topic analysis, source messages and long plan explanations are collapsed by default. Opening these disclosures does not invoke a model, invalidate caches or consume a trial.

Recorded self wording supersedes an earlier pending AI draft. The owner removed the suggestion-history entry: the conversation shows only an eligible reply or wait/pause advice for the current context. Stored old suggestions do not become a separate browsing or copying surface. Full recorded messages and background still feed the current field coach. Failed copy recording preserves the composer; reload restores eligible current-context drafts and copied edits. A receipt for an old-context reply cannot restore it to the UI, and a previous copy cannot replace a later wait decision. Server records remain available for existing feedback and review contracts.

## Personal expression learning — 2026-10-01

A small expression-preference entry in 场外教练 opens the existing personal profile editor. Optional details compare the source suggestion and the user's own draft/version, capture why it changed and distinguish current fit from willingness to learn. User-written rules default to inactive candidates. Explicit adoption and stopping/replacing individual rules use the same profile save transaction; no sent-confirmation or feedback control is added. Preference saves preserve message/plan drafts, do not send a WeChat message and do not invoke a model. Later requested inference uses the adopted account preferences. Recorded counterpart responses remain independent and unassessed, with unknown meaning unknown. Errors and stale-save conflicts retain input for recovery.

## Direction feedback and visual ownership — 2026-10-01

The owner found direction switching too subtle. A selected card now has a solid accent and checkmark; the reply area shows its own generation placeholder, then an actual-direction badge, explicit update status and a brief arrival highlight. Cached results receive the same visible acknowledgement with a saved-result label, without promising different wording. Failure restores the previous direction and edited draft. Reload shows the current stored direction without replaying an update cue. Generation hides the previous draft and disables copying; incoming messages remain recordable and do not infer use of that hidden draft. A late detail read cannot replace a newer accepted reply or discard new messages. Server-derived current suggestion IDs keep old-context drafts out of the active reply area and its copy/follow-up actions. Highlight cleanup is independent of motion, and user-triggered generation keeps keyboard focus on the reply region rather than losing it when direction buttons are rebuilt.

The owner's later explicit correction replaces the earlier purple self bubbles: day mode uses low-saturation pale green for self replies and a white counterpart bubble; night mode uses a muted dark green and neutral counterpart surface. The AI advice card aligns to the self side and shares the reply width, with a lighter related fill to distinguish advice from the draft. The field-coach heat label and action headings receive stronger readable hierarchy. Contextual footnotes appear below coaching text only for terms actually mentioned. Each quiet “注 · 词语” disclosure expands into a small definition box; there is no permanent dictionary or global glossary switch. Definitions use the owner's framework, with refusal and uncertainty handled explicitly.

## Product usability audit — 2026-10-01

A current-state walkthrough found destructive draft resets, late saves overwriting newer input, incomplete-context actions that led only to errors, and keyboard focus escaping the narrow field-coach overlay. The fixes stay inside the existing conversation and companion panel.

Unsubmitted message text, speaker and edit state remain separate per counterpart for the current page session. Reading saved state and editing another record preserve the new-message draft. Canceling or completing an edit returns to that draft; a delayed save clears only its submitted version and cannot enable another submission prematurely. Background intake distinguishes collapse (retain the draft) from cancel (discard that intake draft). Input typed during a background save remains available for a later explicit save. These are in-memory drafts, not a new private-data browser store or a claim of reload persistence.

Before inference is available, the advice area asks for a counterpart alias or the first recorded counterpart message. Profiles and preference questions can be completed gradually; missing answers remain unknown. A failed first reply does not create an empty self-message bubble.

The narrow field coach is a labeled modal with initial focus at its heading, a visible close control, a dimmed background, keyboard containment and Escape/close focus restoration. Its desktop form remains a companion aside. Resizing and opening expression preferences clear the modal state. Semantic conversation regions support accessible naming. The existing green/white speaker roles and on-demand terminology notes remain.

`npm run test:a11y` runs the default axe-core rules over complete fictional pages in day/night and desktop/narrow layouts. It retains both violations and incomplete results for manual review; it does not disable rules or assert full accessibility conformance. Keyboard behavior, reflow, error recovery and data preservation also require the behavioral browser journeys and rendered review.

Feedback for copy/save sits below the conversation toolbar so it stays visible while reading the latest reply. Repeated model failures remain beside their action rather than duplicating the same long error at the top. An object read has a local loading state and retry path; retry success/failure preserves keyboard access and late errors cannot leak into another conversation. The shell clips its contents without becoming a second programmatically scrollable container. Mobile coach headings stay visible during long explanations.

## Quiet recovery and simpler controls — 2026-10-01

The owner removed the recent-operation status list. The conversation keeps its existing advice actions and an optional “补充想法” disclosure; internal provider attempt counts and successful-job diagnostics are not user-facing controls. Current quota limits remain visible when they affect access. A successful suggestion is usable even if the ancillary counterpart-list refresh fails.

The four model actions share bounded recovery: at most three serial HTTP requests per action, with 600 ms and 1400 ms delays. Uncertain transport responses reuse the same request ID to recover the original result. A known persisted transient provider failure may create one replacement request ID; the total retry count never resets. Permission, quota, input, configuration and validation failures do not start automatic replacement calls. Ordinary data writes retain their existing contracts. Existing backend reservations, caches and provider budgets remain authoritative.

Changing account, conversation, context, plan or image explanation stops subsequent recovery requests for the superseded action. Switching away and back cannot resume its retry loop. An already-started model call may still finish under the existing response-isolation rules. Loading remains local to the original action, and drafts stay intact. An exhausted explicit request shows one short explanation and an explicit retry where useful; exhausted automatic analysis retains the initial guidance without an error alert; no job history, error codes or duplicate status message appears. Reload does not launch another recovery sequence for a persisted failed attempt.

## First-message guidance and coach update cues — 2026-10-01

The owner requested an initial range from the first message, default pitfalls when personal evidence is absent, a concrete conversation direction and an obvious current-result update cue. Sparse observed positive evidence uses an uncalibrated 35–75 range; passive/negative observations use 10–45. These ranges are working heuristics, not calibrated confidence intervals or consent. A sufficiently evidenced prior baseline takes priority over a sparse latest observation only while its full recorded input remains compatible: messages may be appended, but correcting prior text, speaker, annotation, timing, profiles or meeting details invalidates the old basis. Prior classifications use insertion order so timestamp ties or clock rollback cannot skip a later refusal. A model that has not analyzed the message produces no fabricated range; the UI shows a local analysis state and usable general guidance. The original multi-dimensional score, trend, top-three and invitation eligibility gates remain intact.

Missing personalized pitfalls receive clearly labeled general guidance for low, ordinary or high observed engagement. Explicit boundaries dominate; neither question marks nor message length alone establishes interest. The main direction says what to talk about or how to develop the conversation, followed by a concrete response approach.

A compact line at the end of the conversation, beside the latest advice, says the coach is updating during inference and that its guidance has updated only after a new current-context result is accepted. The companion heading gains an update badge and a brief border highlight. A “查看” action opens the existing coach on narrow layouts. Reload, repeated saved-result readback, failed or obsolete calls, metadata saves alone and another conversation's result do not create a fresh-update claim. Recovering a previously unseen result after a lost response still announces the actual update, even when the server returns that result from its cache. Context changes clear the old cue. Reduced motion keeps the text without animation. No extra history, confirmation or diagnostics panel is added.

`npm run test:coach-updates` verifies this lifecycle with temporary data and injected providers, including sparse estimates, default pitfalls, refusal, cached results, context/object changes and narrow reduced-motion layouts.

## Contextual terminology notes — 2026-10-01

The owner replaced the dictionary-style glossary with unobtrusive annotations attached to current coaching content. Only terms present in the coach's displayed guidance are offered; expanded reasoning can add its own referenced terms. Raw chat quotations, the user's unsent plan and the definitions themselves are excluded from matching. “上堆” uses the existing “上切” definition. Generated plan assessments get the same notes immediately below their result.

Notes default to a small muted disclosure row and open into a lightly bordered definition box. Unmentioned terms take no space. Re-rendering the same context preserves the open state of surviving notes; a changed context resets it, and removed terms leave no stale definition behind. Keyboard access, readable contrast and 44px touch targets remain. Reading or closing a note does not call a model, change context, or modify message/plan drafts.

## Background learned from recorded conversation — 2026-10-01

The owner requested progressive intake and automatic background/meeting updates. A counterpart alias is enough to start; personal background, recognition channel details and preference answers are optional. Unanswered questionnaire items are never filled with neutral answers or fabricated traits. The full questionnaire remains paid-only.

Every normal classification or reply can also return evidence-backed background facts and meeting progress from the complete recorded conversation. This shares the existing model request and allowances. The existing profile/background panels display those facts in a quiet read-only group; manual fields remain available for additions and corrections. Facts about the user's own background stay labeled with the current conversation, not silently generalized into the account's identity or adopted expression preferences. Meeting status, time and place populate the existing arrangement fields automatically. No separate confirmation, extraction action or activity feed is introduced.

Automatic facts are projections of the saved analysis and original message evidence, not replacements for the original records. They do not enter shared knowledge or training. Stale projections are withdrawn after source edits; the next analysis rebuilds them from the full context. The source profiles and complete recorded messages remain model input, so projected summaries cannot cause recursive cache invalidation or replace the full history. Unsent suggestions and user initiative drafts are excluded. Proposed and mutually agreed meetings remain distinct. A manual arrangement correction prevails over the messages that existed when it was saved; later chat can update it again.

The UI uses the manual arrangement for request identity, so rendering an automatic update does not spend another model call. An in-progress manual correction survives analysis and switching between conversations during the page session. Reload reads eligible stored projections without generating a request, including when changed knowledge or model policy has invalidated an earlier result.

New messages from either speaker can trigger the existing eligible automatic analysis once there is a counterpart message. Exhausted analysis trials still require an explicit reply request under the existing free-reply allowance; there is no hidden extraction call. Saving optional intake alone does not invoke a model. Late detail reads cannot roll back a newly accepted classification or reply. Evidence validation establishes links to supplied records, not independent verification of someone's biography or a guarantee of natural-language extraction accuracy.

## Conversation directory — 2026-10-01

Desktop uses the left margin for a WeChat-like conversation directory. Each row shows the saved remark or name, the original name when a remark is present, a short preview of the last counterpart reply, and a compact reference heat such as `79°`. The optional remark is display metadata and does not become a model instruction. Existing records default to an empty remark without a database migration.

Users choose recent counterpart reply or descending reference heat. Profile edits and outgoing messages do not count as incoming replies. The corrected WeChat time takes precedence over recording time; the preview always belongs to the last counterpart message in recorded order. Sorting does not switch the selected conversation or discard drafts. Unknown heat has no invented number; explicit refusal displays a pause. The selected sort mode is the only directory data stored in localStorage.

At 1280px and above the directory, chat and coach are three columns. At 761–1279px the directory remains visible and the coach uses its existing overlay. At 760px and below the native conversation picker remains the single selection entry. A read-only minute refresh while visible updates directory heat without model calls, quota consumption or automatic selection. Account and request-order guards reject stale reads. Detailed aging rules are in `docs/heat-context.md`.

The inline AI card no longer labels sparse or not-yet-analyzed context simply “信息不足”. A recorded counterpart message is enough to offer a general initial direction: respond to what was actually said and naturally learn one useful detail. The companion identifies this as general guidance until a current result is available. A completed sparse analysis can still supply a provisional range, working focus and concrete action; lack of an exact score does not block coaching. Actual waiting/stop instructions take precedence over the generic information-gathering direction.

With no counterpart message, the interface asks for one original line rather than complete background forms. During a model failure, general guidance remains usable but no completed-analysis cue or invented temperature appears. Previously completed model guidance retains its own attribution. No additional inference, quota, confirmation or feedback step is added.

## Read-only reopening and auxiliary extraction isolation — 2026-10-02

Opening, refreshing, switching conversations and retrying a failed detail read only restore saved state. A missing current analysis, including one invalidated by a knowledge or protocol change, is not an instruction to spend another model call. Only recording a new message or explicitly requesting advice can initiate the existing analysis flow. Real in-progress analysis still shows its update cue, and completed new results retain the completion cue. Initial guidance is available when no current analysis exists.

Auxiliary background extraction is validated independently from core coaching. Invalid facts are dropped individually; duplicate or conflicting subject/field groups are all dropped. An invalid meeting becomes absent without changing a manual arrangement. Valid independent facts and meeting evidence remain usable; malformed auxiliary structure becomes an empty projection. Only validated projections are stored, and readback keeps strict evidence checks. Missing required core fields, invalid heat evidence and invalid coaching output still fail. This uses the same response, with no additional provider call or quota.

## Reply visibility and quiet feedback — 2026-10-02

Generated and restored suggestions scroll to their beginning inside the conversation, so the first line remains visible. The bordered “复制回复” action sits beside the reply heading and acknowledges successful copying with “已复制” for three seconds. Editing, a new suggestion, or visiting another conversation invalidates that acknowledgement. Delayed clipboard outcomes stay scoped to their original conversation. Wait/pause advice and generation expose no copy action.

Routine success notices dismiss after five seconds; errors and active progress remain available. A newer message cancels the older notice's timer. Copying a reply uses local button feedback, without a page-wide success banner.

Deleting an edited message restores the preceding composer draft. Failed deletion preserves the edit. Late deletion results for one counterpart preserve another counterpart's current fields, reply draft and focus; stale detail responses cannot restore a deleted counterpart. These changes add no provider calls or persistence contracts. Isolated browser regressions cover desktop and narrow layouts, refresh/switch restoration, clipboard delays and deletion races.

## Clear affordances and next-step guidance — 2026-10-02

The owner found controls discoverable only on hover, weak next-action guidance and broken interaction states in both day and night themes. Following LYNCA Design Standard 1.4.0 interaction-state rules (§5.1), controls now use four tiers: Solid for primary actions, Outline for secondary actions and menu triggers, accent text with a chevron for disclosures/links, and full-width borderless menu rows. Disabled labels use explicit colors and dashed control borders rather than faded opacity; keyboard focus and 44px targets remain.

The shared token block adds `--color-control-line`, `--color-hover`, `--color-press`, `--color-accent-strong` and `--color-disabled-text` for each theme. Explicit alpha overlays replace accent-soft hover fills; no application `color-mix()` is used. Hover applies only to fine pointers that support it. Touch uses the same visible rest affordances. The selected directory row retains its static accent-soft fill with an accent inline-start indicator.

Exactly one action in record → advice → copy is highlighted, or none while the current model call is preparing without a composer draft. A persistent, wrapping hint above the composer identifies the next step from existing context, input and copy receipts. Timing and keyboard help share one muted line. These DOM-derived cues add no requests or storage.

Message annotations open through `⋯ → 添加批注 / 编辑批注`, with focus in the existing editor. Empty closed annotations stay hidden; saved background retains the `批注 · 已补背景` disclosure. Draft, pending-save, error and focus recovery remain intact.
